# Модель данных

Всё хранится в JSON. Три корневых типа объектов.

## Корневые типы

### Event Object

Событие — то, что произошло.

    id, name, description

**Этого мало.** В текущем виде по событию нельзя искать: нет ни времени,
ни участников, ни места. Значит второй этап доступа к памяти не сможет
ответить на «что было у игрока с этим NPC раньше». Необходимый минимум:

    id, name, description,
    when        — тик, когда произошло
    who         — список id участников
    where       — id региона
    importance  — значимость, для ранжирования при доборе
    refs        — ссылки на связанные Memory Object

Без этих полей память не запрашиваемая, а просто свалка текста.

### Memory Object

Постоянная сущность мира: кто правит, где что лежит, кто есть кто.

    id, type (класс), name, ...

`type` играет роль тега: по нему берут «все объекты такого рода».

### Battle Object

**Хранилище префабов для инициализации боя.** Не отдельная жизнь объекта,
а заготовка, из которой бой собирается.

    id, type (класс), name, isBreakeble, pos, size

У `person` и `mob` есть поле `battle`, указывающее на их боевой префаб.
Возможность позвать префаб напрямую тоже сохраняется — для засад и
статистов, у которых нет своей записи в памяти.

## Классы

| Класс | Назначение |
|---|---|
| `Plain` | мир: `Territoryis`, `Gouverment`, `Ideology` |
| `domain` | домен, содержит `SelectionTree` |
| `skill` | навык, содержит описание |
| `person` | разумное существо, см. `Person/` |
| `mob` | неразумное наполнение природы |
| `Live` | боевой префаб существа: контейнер характеристик |
| `Alive` | боевой префаб клетки поля |

`Culture` и `Religion` слиты в `Ideology` — сознательное упрощение,
`god` внутри идеологии ложится на лор с верой мирян.

### Live и Alive

**`Live`** — контейнер характеристик существа, префаб для боя. Привязан
к своему Memory Object (`person` или `mob`).

    properties, effects, hit, speed, skills

**`Alive`** — префаб клетки поля боя: вода, трава, преграды (колонны,
стены), следы заклинаний. К памяти **не привязан**, живёт только
внутри боя.

    properties, hit

> **Имена сбивают с толку.** `Live` и `Alive` — синонимы в английском,
> а обозначают существо и клетку земли. Живая клетка воды читается как
> ошибка. Стоит переименовать в `Combatant` и `Tile`, пока это правка
> на вечер, а не на всю кодовую базу.

### Способности

Разделение булево, на каждом уровне:

    canDamage / notCanDamage
      can:    damage, effects, properties, rangetype
      heal / notHeal
        heal:    effects, properties, rangetype
        notHeal: effects, properties, rangetype

`damagetype`, `healtype`, `heallight` убраны — тип уехал в `properties`.

### properties

Сам по себе класс:

    тип навыка
    особенности     — например, чем этому можно противодействовать
    вложенные конструкторы функций

> **Риск свалки.** Сюда уже сложены тип навыка, особенности, конструкторы
> функций и состояние носителя домена. Нужен тег `kind`, иначе через
> полгода не разобрать, что внутри.

## Мир

### Territoryis

Сетка 100×100 регионов по 100 км². Регион содержит:

    население, ресурсы (еда, товары, золото), биом

Простой бот распределяет ресурсы по условным правилам: товары дают больше
еды, еда — больше людей, люди отдают деньги и потребляют еду и товары.

> **Десять тысяч регионов — это симуляция уровня Paradox.** Каждый тик
> бот проходит по миллиону квадратных километров, и 99% этой работы
> игрок никогда не увидит.
>
> Нужен **LOD симуляции**: регион рядом с игроком считается полностью,
> дальше — агрегированно на уровне `Gouverment`, далеко — заморожен
> и досчитывается одной формулой при визите. Так делают Dwarf Fortress
> и RimWorld.

### Gouverment

    тип правления, описание,
    глава (если есть), наследник (если есть),
    подвластные region, законы,
    армия: Army → Division { id, name, manpower, pos(region), armament }

### Ideology

    rules,
    население (распределение по регионам),
    god (если религия; в светской идеологии — наставник)

## Состояние носителя домена

Бывший `state_player`. Принадлежит **любому** носителю домена, не только
игроку. Хранится в `person.properties`, если персонаж — бог.

    domains, skills, ash, constellations, ...

## Battle Object и рассинхрон

Поскольку `Battle Object` — это префаб, а не вторая жизнь сущности,
результат боя обязан **писаться обратно** в Memory Object. Иначе NPC,
убитый в бою, останется живым в памяти мира.

Правило: бой читает из префабов, но исход применяется к сущностям.

# Память и доступ к ней

## Двухэтапная схема

1. **Короткий этап.** Модель анализирует ситуацию в режиме мышления.
2. **Добор.** Если контекста не хватает, модель запрашивает недостающее
   из памяти и обновляется.

Плюс сжатие истории в краткие сводки.

Схема правильная, но у неё три условия, без которых она не работает.

### 1. Предзагрузка по графу, а не чистый добор

Бóльшая часть нужного контекста **выводится из ситуации детерминированно**:
где игрок → регион → правительство → идеология → кто присутствует. Это
обход графа в БД, без единого обращения к модели.

Добор нужен только для непредсказуемого: «что у меня было с этим NPC
сорок ходов назад». Заставлять модель догадываться о том, что и так
известно, — значит платить лишним вызовом за известное.

### 2. Лимит раундов добора

Если модель может попросить ещё контекста — она будет просить. Три добора
подряд это четыре вызова на ход, на трёх ролях — двенадцать. Токены платит
игрок.

Потолок: **один добор, в исключении два**, со счётчиком.

### 3. Сжатие обязано быть обратимым

Самая частая смерть таких систем: сжали в сводку → детали потерялись →
через двадцать ходов ИИ противоречит сам себе, и починить нечем, потому
что оригинала не осталось.

Правило: **сводка идёт в контекст, полный текст остаётся в БД** и
достаётся тем же вторым этапом. Сжатие перестаёт быть удалением
и становится понижением приоритета.

Рабочий пример этого подхода уже есть в проекте: `MentalState.recent()`
ранжирует эпизоды по `weight × |valence|`, в промпт отдаёт три, остальные
лежат в `state.episodes` и никуда не деваются.

## Граф — это то, что уже есть

Граф не требует ни отдельной базы, ни новой технологии. Граф — это
**записи со ссылками друг на друга по id**. В схеме их уже полно:

    Gouverment.подвластные_region  → ссылка на регионы
    Division.pos(region)           → ссылка на регион
    person.current_world           → ссылка на мир
    person.family                  → ссылки на других person
    person.battle                  → ссылка на боевой префаб
    Event.who / Event.where        → ссылки на участников и место

Каждая такая ссылка — ребро. Записи — вершины. Граф уже построен.

### Чего не хватает: обратного индекса

Сейчас из `Gouverment` можно узнать его регионы. А из региона узнать,
кто им правит, — нельзя, не перебрав все правительства.

Лечится одним индексом «кто на меня ссылается», который строится
за один проход по данным:

```python
def build_backlinks(objects: dict[str, dict]) -> dict[str, list[str]]:
    """{id: [id тех, кто на него ссылается]}"""
    back: dict[str, list[str]] = {}
    for oid, obj in objects.items():
        for target in refs_of(obj):        # поля-ссылки этой записи
            back.setdefault(target, []).append(oid)
    return back
```

### Обход = сборка контекста

Взять стартовый id и пройти по ссылкам на N шагов:

```python
def gather(start_id: str, depth: int, objects, back) -> dict:
    seen, frontier = {start_id}, [start_id]
    for _ in range(depth):
        nxt = []
        for oid in frontier:
            for nid in refs_of(objects[oid]) + back.get(oid, []):
                if nid not in seen:
                    seen.add(nid)
                    nxt.append(nid)
        frontier = nxt
    return {i: objects[i] for i in seen}
```

Контекст сцены для игрока в регионе `R` при `depth=2`:

    R  → биом, население, ресурсы
    R  ← Gouverment G        (через обратный индекс)
    G  → глава, законы, армия
    R  ← person, находящиеся здесь
    население R → Ideology

Это весь контекст сцены. **Ноль вызовов модели.**

### Граф и теги не конкурируют

Две ортогональные оси поиска, нужны обе:

| Ось | На какой вопрос отвечает | Чем реализуется |
|---|---|---|
| граф | «что связано **вот с этим**» | ссылки по id + обратный индекс |
| тег | «дай всё **такого рода**» | поле `type` |

Исходный план — `type` как тег плюс доступ по `id` — верный. Граф просто
даёт третий способ спросить, и он уже заложен в структуре.

### Эмбеддинги пока не нужны

Они отвечают на «найди что-нибудь **похожее на**». Пока ИИ спрашивает
«дай мне вот это» и «что связано с этим», граф и теги справляются, и они
на порядок дешевле. Добавить эмбеддинги можно позже, если упрёшься
в семантический поиск — структура данных от этого не меняется.

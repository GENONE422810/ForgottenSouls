# Документация Forgotten Souls

Материалы для того, чтобы новый человек или агент вошёл в проект без
пересказа в чате.

## Порядок чтения

| Файл | О чём | Кому |
|---|---|---|
| `01-concept.md` | что за игра, лор, космология, правовая позиция | всем |
| `02-architecture.md` | поток данных, три роли ИИ, `TePa` | всем |
| `03-data-model.md` | объекты, классы, мир, состояние носителя домена | кто трогает БД |
| `04-memory.md` | двухэтапный доступ к памяти, граф, сжатие | кто трогает ИИ |
| `05-mechanics.md` | душа, домены, мыслесила, заклинания, бой | кто трогает механику |
| `06-gameplay.md` | игровой цикл, ход боя, прогрессия, что игрок делает руками | всем |
| `DECISIONS.md` | принятые решения и почему именно так | всем |
| `OPEN-QUESTIONS.md` | что ещё не решено | всем |
| `FINDINGS.md` | найденные ошибки в `Person/` и `AI/` | кто трогает код |

Минимум для правки кода: `01`, `02`, `06`, плюс тот файл, который относится
к задаче. `DECISIONS.md` читать обязательно — там лежат решения, которые
выглядят спорными, пока не знаешь причины.

## Как поддерживать

`FINDINGS.md` — единственный файл, который должен сокращаться: починил
пункт, убрал его оттуда тем же коммитом. Если по ходу починки выяснилось
что-то, чего там не было, — дописать.

Документация идёт тем же коммитом, что и код, который её меняет.
Решение, у которого есть неочевидная причина, записывается в
`DECISIONS.md` — иначе через полгода его отменят по незнанию.
Нерешённое идёт в `OPEN-QUESTIONS.md`, а не в голову автора.

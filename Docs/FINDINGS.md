## 1. Кеш `stable` протухает для всех собеседников, кроме первого

`Person/person.py:197`, метод `system_prompt()`. **[проверено]**

```python
key = (who.name if who else None, private)
if self._dirty or key not in self._cache:
    self._cache[key] = render(...)
    self._dirty = False          # сбрасывается после ОДНОГО ключа
```

Ключ кеша — `(имя собеседника, private)`. После `touch()` пересобирается
запись только для того собеседника, чей промпт запросили первым. Для всех
остальных `_dirty` уже `False`, и берётся устаревший `stable`.

Воспроизведение: персонаж учит навык `интриги`, вызывается `touch()`,
затем запрашиваются промпты для двух разных собеседников.

    интриги в промпте для Аэн  : True
    интриги в промпте для Борна: False      <- должно быть True

Последствие: NPC выучил навык, сменил цель или сдвинул архетип — и часть
собеседников об этом не узнает до перезапуска.

Отдельно: в `else`-ветке всё равно вызывается полный `render()`, из
которого берётся только `volatile`, а `stable` выбрасывается. `render`
детерминирован от снимка, поэтому повторный вызов дал бы ту же строку.
Кеш не экономит ни такта и приносит только этот баг.

Направление: убрать кеш целиком и рендерить каждый раз. Если экономия
понадобится — кешировать по-настоящему, ключом от содержимого стабильной
части, а не флагом `_dirty` на весь объект.

## 2. `privacy="isolate"` меняет порядок говорящих

`AI/Roles/empath.py:116`, метод `_group()`. **[проверено]**

```python
groups = [[m] for m in solo]                       # носители тайн
groups += [pack[i:i + batch_size] for i in ...]    # все остальные
```

Носители тайн уезжают в начало списка групп, и `play()` обходит группы
в этом порядке.

    состав  = ['Без-тайн-1', 'Аэн', 'Без-тайн-2']
    redact  -> ['Без-тайн-1', 'Аэн', 'Без-тайн-2']
    isolate -> ['Аэн', 'Без-тайн-1', 'Без-тайн-2']

Это не косметика: персонажи видят реплики, сказанные до них в том же
круге (см. `DECISIONS.md`, «Эмпат делает отдельный вызов на персонажа»).
Смена очерёдности меняет содержание сцены — причём выбор политики
приватности не должен влиять на то, кто говорит первым.

`crowd_check()` проверяет порядок только на дефолтном `redact`, поэтому
не ловит.

Направление: собирать группы, сохраняя позицию первого участника каждой
группы в исходном составе, и обходить их в этом порядке.

## 3. Эпизоды памяти растут без границы

`AI/Roles/empath.py:235`, метод `_write_memory()`. **[проверено]**

Эпизод пишется каждый круг. Вес гасит и мусор выкидывает только
`state.tick()`, который в диалоге не вызывается (см. п. 4).

200 ходов с одним персонажем:

    эпизодов: 200        вес первого: 0.4 (не изменился)
    сейв персонажа: 20.6 КБ

`Person/README.md` обещает «~2 КБ на персонажа». Все 200 эпизодов —
почти дубликаты вида `разговор: «...»`, и `recent()` сортирует весь
список на каждом вызове.

Вдобавок `valence = m.person.state.mood.pleasure * 0.5` — это просто
текущее настроение, которое ничем не менялось, то есть эмоциональная
метка эпизода несёт нулевую информацию.

Направление: решается вместе с п. 4. Минимум — вызывать `tick()` на ходе
и не писать эпизод на каждую реплику, а только на значимую.

## 4. Слой эмоций построен, но ничем не приводится в движение

`Person/state.py`. **[проверено]**

`state.apply()` и `state.tick()` не вызываются нигде, кроме разогрева
стартового состояния в демонстрациях:

    AI/dryrun.py:67     guard.state.apply(...)   <- setup
    Person/demo.py:47   g.state.apply(...)       <- setup

Ни одного вызова из `Empath` или любого другого рабочего кода.

Следствия: настроение NPC не меняется от того, что ему говорят;
отношение не сдвигается; силы не тратятся; потребности не растут;
старые воспоминания не гаснут (п. 3).

`state.py` открывается словами «без этого слоя NPC на 40-м часу игры
ведёт себя ровно как на первом» — сейчас именно это и происходит.
Всё написано, не хватает только того, кто дёргает рычаг.

**Требует решения, а не просто починки.** Решать, как реплика ударила
по персонажу, должна симуляция, а не модель — иначе нарушается
«ИИ не имитирует механику, а вызывает её» (`DECISIONS.md`). Варианты:

- детерминированный оценщик реплики на стороне механики;
- Narrator выдаёт дельты через служебный вызов `TePa`.

Развилку стоит пройти до Этапа 1, потому что от неё зависит форма
контракта роли.

## 5. У `Person` нет `id`, сцена хранит персонажей по значению

`AI/scene.py:77` (`to_dict` кладёт `m.person.to_dict()`). **[по чтению]**

`Docs/03-data-model.md` описывает `person` как Memory Object с `id`,
`type` и ссылками по id, плюс `person.properties` под состояние носителя
домена. В коде у `Person` нет ни `id`, ни `properties` — только `name`.

Отсюда:

- `Scene` сериализует персонажей внутрь `scene_*.json`. Один NPC в двух
  сценах — две копии, которые разъедутся;
- идентичность везде по имени: `scene.find(name)`, `attitudes[name]`,
  `_others_block` сравнивает `o.name == me.name`. Двух персонажей
  с одинаковым именем система не различит;
- граф из `04-memory.md` целиком построен на id и к текущему `Person`
  не пристыкуется.

**Требует решения.** Это работа Этапа 0 («Схемы данных»). Каждый прогон
`main.py` уже кладёт на диск сейв в формате, который придётся
мигрировать, поэтому дешевле сейчас.

## 6. `Completer` не передаёт температуру и модель

`AI/Roles/empath.py:44`. **[по чтению]**

```python
class Completer(Protocol):
    def complete(self, system: list[str], messages: list[dict]) -> str: ...
```

Ни температуры, ни модели, ни `max_tokens`. В `AI/client.py:31` они
зашиты в дефолты (`temperature=0.9`, `max_tokens=300`), модель одна
на всё из `OPENROUTER_MODEL`.

`DECISIONS.md` требует обратного: «каждой роли своя модель: Judje —
точность и низкая температура, Empath — выразительность». Judje,
написанный поверх этого протокола, получит `temperature=0.9`.

Направление: расширить протокол до появления второй роли — потом
править придётся все роли сразу. Параметры сэмплинга и выбор модели
должны жить в конфиге роли, а не в глобальной env-переменной.

## 7. Стоимость меряется в символах, а не в токенах

потянет ли игра три роли на ход. Мерить надо в той единице, в которой
выставляют счёт. Вывод про пакет, скорее всего, устоит, но проверить
его стоит заново.

## 8. Устаревшая модель по умолчанию

`AI/client.py:17`. **[по чтению]**

```python
DEFAULT_MODEL = os.getenv("OPENROUTER_MODEL", "anthropic/claude-3.5-sonnet")
```

Модель из давно не актуального поколения. Актуальный слаг надо брать
из списка моделей OpenRouter, а не выводить из памяти: у OpenRouter
свои провайдер-префиксные имена, и они меняются.

Сам заход через OpenRouter на OpenAI-совместимом SDK менять не нужно:
при схеме «ключ игрока» это как раз правильно, игрок выбирает любого
провайдера.

Но дефолт должен переехать из глобальной env-переменной в конфиг роли,
вместе с п. 6.

## 9. `dryrun` не умеет провалиться

`AI/dryrun.py:112`. **[по чтению]**

```python
for label, ok in checks:
    print(f"  [{'OK' if ok else 'ПРОВАЛ'}] {label}")
```

Печатает результат, но код возврата всегда 0. Регрессию не заметит

`ROADMAP.md` объявляет Этап 0 готовым тогда, когда «весь цикл гоняется
на болванках» — то есть `dryrun` и есть приёмочный тест этапа, а сейчас

Направление: ненулевой код возврата при провале, а лучше перенести
проверки в pytest и оставить `dryrun` для глазного осмотра промптов.
Баги 1–3 должны попасть в тесты, чтобы больше не проходить молча.

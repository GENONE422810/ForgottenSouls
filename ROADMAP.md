# Forgotten Souls — план разработки

Принцип порядка: **сначала то, что может не получиться.** Механики души,
домены и созвездия — работа, которая точно сделается. Удержит ли Narrator
связность, не развалится ли формат вызовов, сколько стоит ход в реальных
токенах — неизвестно, и узнать надо до того, как под это написано полгода кода.

## Архитектура в одном абзаце

`Pte` (ввод игрока) → `TePa` (парсер, вынимает `#'заклинание'` и тянет его
характеристики из БД) → `RoHa` (менеджер ролей) → `Narrator` как Game Master,
который по надобности дёргает `Empath` (отыгрыш NPC) и `Judje` (оценка боя).
Ответ ИИ идёт обратно через `TePa`, который ловит служебные вызовы вида
`[Inicialise:battle:creep1,creep2]` и исполняет их детерминированно.
Вне боя игровых объектов нет — всё живёт описанием, пока Narrator не
инициализирует бой. `WoRu` симулирует мир, `EvSy`/`EvTe` порождают события,
`SaMa` сохраняет.

ИИ работает в два этапа: короткий анализ в режиме мышления, затем добор
недостающего контекста из памяти. Плюс сжатие истории в сводки.

---

## Этап 0. Хребет — без единого токена

Всё детерминированное, тестируется на заглушке.

- `TePa` в обе стороны + тесты: вынимать `#'...'` из ввода игрока,
  ловить `[...]` в выводе ИИ, валидировать аргументы по БД
- Схемы данных: Event / Memory / Battle объекты, классы, `state_player`
- Слой памяти: хранилище, индекс связей, запрос по графу
- Типизированные контракты ролей — что каждая получает и возвращает.
  Не строки: схема, которую можно провалидировать
- Весь цикл гоняется на `StubLLM`, как `AI/dryrun.py` сейчас

**Готово, когда:** сцена «комната → действие → бой → исход» проходится
целиком на болванках, и ни один вызов не идёт в сеть.

## Этап 1. Вертикальный срез в терминале

- `RoHa`: собрать выход трёх ролей в один ответ
- `Narrator` минимальный: описывает сцену, принимает действие, умеет
  `[battle]`. Пишется как машина состояний с ИИ внутри, не как один промпт
- `Empath`: готов, подключить
- `Judje` минимальный: одно действие, таблица 0–20 → коэффициент 0.2–2.0,
  проверка выполнимости, состояние боя с позицией и скоростью
- Godot не трогаем

**Готово, когда:** играется без слома формата и без ручного вмешательства.

## Этап 2. Экономика и надёжность

- Замер стоимости хода на живых моделях
- Валидация вывода по схеме + ретраи
- Своя модель под каждую роль: Judje — точность и низкая температура,
  Empath — выразительность, Narrator — длинный контекст
- Проверка ключа игрока прогоном эталонных кейсов
- Полное сохранение и загрузка

**Готово, когда:** цена хода известна и приемлема.

## Этап 3. Механики души

- Мыслесила, нагрев, пепел, счётчик Исхода
- Домены, девять аспектов души, дерево выбора путей
- Заклинания: формат и рантайм контуров, **без редактора**, пока текстом
- Чудеса без ритм-игры, авто-успех

## Этап 4. Godot

- UI поверх готовой логики
- Протокол — локальный сервер, а не встраивание Python в движок

## Этап 5. Режется первым при нехватке времени

Визуальный редактор кругов, ритм-игра чудес, созвездия, миряне и жрецы,
Исход как полноценная арка, бесконечная генерация мира.

## Риски

**Narrator — самое недооценённое.** На порядок сложнее Empath: держит
связность, помнит историю, не противоречит себе, выдаёт структурированные
вызовы. Один большой промпт не вытянет. Детерминированный каркас сцены плюс
ИИ только на описание и выбор из ограниченного набора.

**Три роли — три разные модели.** Одна модель на всё будет одновременно
дорогой и плохой. Модель задаётся в конфиге роли с первого дня.

**Ключ игрока = качество вне твоего контроля.** Дешёвая модель → Judje врёт →
виновата игра. Нужен прогон эталонных кейсов при подключении ключа.

**Остановка WoRu на диалоге.** Мир на паузе игрок заметит. Лучше не
останавливать, а откладывать: копить события и применить после диалога,
показав как «пока вы говорили…».

**Масштаб.** Объём на годы для одного человека. Вытягивается только жёстким
вертикальным срезом: довести до играбельности узкую полосу, остальное резать.
